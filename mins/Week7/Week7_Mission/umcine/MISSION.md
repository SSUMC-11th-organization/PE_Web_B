# 7주차 미션 기록

## 본문 실습: 회원가입

- `src/utils/member-validation.ts`: 이메일 형식, 닉네임 2~12자, 비밀번호 영문 대소문자·숫자·허용 특수문자 포함 8자 이상, 비밀번호 확인 일치 검사.
- `src/api/members/`: 이메일·닉네임 중복 확인과 회원가입 API 요청 함수 분리. 경로 입력값을 URL 인코딩하고 회원가입 요청에는 email·nickname·password만 전송.
- `src/pages/auth/signup-page.tsx`: useState로 입력값·요청 상태 관리. 모든 검증과 두 중복 확인을 통과해야 제출 가능. 값을 바꾸면 중복 확인 초기화.
- 요청 중 입력·버튼 비활성화, useRef로 빠른 연속 요청 방지. 실패하면 입력 유지, 성공하면 서버 메시지 안내 후 로그인 이동.
- HTTP 오류와 `isSuccess: false` 업무 실패 모두 처리.

## 필수 미션: 로그인과 내 정보 화면

- `/login`: 이메일·비밀번호 입력과 검증, 아이콘, 제출 버튼, 회원가입 링크.
- `/profile`: 기본 정보와 내 즐겨찾기, 정보 수정 링크 및 TMDB 출처 표시.
- `/profile/edit`: 닉네임과 프로필 이미지 수정, 이메일 읽기 전용, 변경사항 저장.
- 프로필 이미지는 JPG·PNG·WebP·GIF, 최대 5MB. 선택 즉시 미리보기, 저장하면 조회 화면에 반영.
- `src/stores/profile-store.ts`: 프로필을 메모리에 저장. 저장하지 않고 페이지를 나가면 기존 정보 유지. 새로고침하면 디자인 예시로 초기화.
- 로그인·내 정보 조회/수정 API는 8주차 범위이므로 미연결. 수정 화면의 닉네임 중복 확인과 회원 탈퇴는 미연결 안내 표시.
- 즐겨찾기는 퍼블리싱용으로 디자인의 예시 3편을 표시하며 실제 회원의 즐겨찾기 API와는 미연결.

## 최종 확인

- `pnpm fix`, `pnpm check`, `pnpm typecheck`, `pnpm lint`: 통과.
- `pnpm build`: TypeScript 검사 및 프로덕션 빌드 통과.
- 브라우저: 각 페이지 직접 접근, 입력 검증, 헤더·회원가입·정보 수정 링크 확인.
- 임시 로컬 테스트 API: 중복 값·사용 가능한 값·서버 오류, 요청 중 비활성화, 중복 확인 초기화 확인.
- 임시 로컬 테스트 API: 회원가입 업무 실패 후 입력 유지, 성공 후 로그인 이동, 요청 body의 필드 확인.
- 브라우저: 닉네임·이미지 선택 후 저장 및 조회 반영, 미저장 변경 보존 안 됨, 이메일 읽기 전용, 유효하지 않은 닉네임 저장 방지 확인.
- 1440px 화면에서 디자인 대조. 390px 모바일에서 회원가입·내 정보·수정 화면 가로 넘침 없음 확인.
- 프로필 정적 이미지·아이콘의 로딩과 표시 크기 확인.

추가로 기존 Spring Boot 회원 서버를 H2 임시 메모리 DB로 실행해 실제 API를 검증했다. 가입 전 이메일 사용 가능, POST /members 201 성공, 가입 후 이메일·닉네임 사용 불가, 중복 가입 409와 CORS 허용 응답을 확인했다. 브라우저의 실제 서버 회원가입 흐름도 확인했다. 기존 MySQL 데이터는 변경하지 않았다.
